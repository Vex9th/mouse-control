# 迈从官网只读数据采集

用于核对 MouseControl 的设备识别、电量、当前 DPI 与回报率。适用于本次 `3837:1018` 共用接收器使用的 `0x4D` 新协议；其他协议会保留报告摘要，但不会误称已经抓到可解析读数。

## 需要提供什么

- 鼠标的完整型号（例如 A5 V3 Pro，而不是只写 A5）、连接方式（有线 / 2.4G 接收器），以及官网显示的鼠标和接收器固件版本（若有）。
- 官网显示型号、电量、DPI、回报率的截图；不同页面可以分别截图。
- 以下步骤导出的 `mousecontrol-mchose-readonly.json`。
- 在 MouseControl 1.5.2 中点击一次刷新后，从“诊断日志”复制的报告。历史记录可能保留 1.5.1 的旧错误，请连同最新时间和每条记录的版本一起提供。

这些数据可核对原始响应与官网读数。普通“另存为网页”、控制台报错文字或网络 HAR 文件，不能代替 WebHID 设备报文。

## 操作步骤

1. 在 Windows 的 Chrome 或 Edge 中打开 [迈从 M HUB](https://www.mchose.com.cn/#/connectDevice)。先关闭其他正在查询鼠标的驱动窗口和 MouseControl，暂不点击网页的连接按钮。如果已经连接，刷新页面后从第 2 步开始。
2. 打开 [采集脚本](../scripts/mchose-capture.js)，复制文件的全部内容。脚本只在迈从官方 HTTPS 页面运行；源码可直接查看。
3. 在官网页面按 `F12`，选择 **Console / 控制台**，粘贴脚本并按回车。等待出现采集已启动的提示。也可在 **Sources → Snippets** 中保存为片段后运行。
4. 回到官网，点击连接设备，在浏览器的授权窗口选择这只迈从鼠标或接收器。打开 DPI / 性能设置页面，等待约 20 秒，让官网读出当前数值。**这轮无需修改任何设置。**
5. 截图记录官网显示的型号、固件和读数。不要刷新或关闭此页面，否则当前采集记录会丢失。
6. 在控制台输入下列命令并回车，浏览器会下载 JSON，同时停止采集：

   ```js
   MouseControlCapture.save()
   ```

7. 保存官网 JSON 后，关闭官网驱动页面，再打开 MouseControl 1.5.2，刷新一次并复制最新诊断日志。把日志、JSON、截图和完整型号一起发回。文件可直接作为聊天附件，或手动附到 GitHub Issue；脚本不会自动上传。

查看采集状态：

```js
MouseControlCapture.status()
```

提前停止但暂不下载：

```js
MouseControlCapture.stop()
```

停止后仍可调用 `save()` 导出已保留的数据。需要重新采集时，先保存，再刷新官网并重新安装脚本。若要分别测有线与无线，两次单独采集，下载后将文件重命名为 `型号-有线.json`、`型号-无线.json`。

## 如果显示零条有效报文

仍可导出摘要，但这不算采集成功。先确认脚本在点击连接之前运行，并且官网确实显示当前读数。若一直为零，连同型号、官网截图和导出的摘要一起提供，可能需要适配另一种迈从协议。不要随机改配置或发送控制台 HID 命令。

## 记录范围

脚本只旁观官网现有的通信，自身不打开设备、不请求新权限、不发送任何 HID 指令，也不切换配置。只保存 VID `3837`、报告 ID `4D` 中读取设备信息 `0900`、当前配置 `0002`、DPI 表 `0003` 的原始请求和响应；其他报告仅统计命令、报告 ID 与长度，不保存其内容。

JSON 包含时间、浏览器版本、USB VID/PID、产品名称、报告描述符摘要及最多 512 条读取报文，达到上限会显示丢弃数量。不读取 Cookie、账号令牌、序列号或本机文件，不记录正常鼠标移动和键盘输入，不发送网络请求。停止时移除自己的监听，并在仍持有原包装函数时恢复官网接口。

这是诊断辅助工具，离线测试不能替代朋友电脑上的实测。只读日志也不能证明 DPI / 回报率写入已经正确；后续设置功能需要独立验证设置指令、返回确认及持久化行为。

原理参考：[WebHID 输出报告](https://developer.mozilla.org/en-US/docs/Web/API/HIDDevice/sendReport)、[输入报告事件](https://developer.mozilla.org/en-US/docs/Web/API/HIDDevice/inputreport_event)。
