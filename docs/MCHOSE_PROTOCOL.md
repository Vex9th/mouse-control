# 迈从鼠标：实验性只读适配

本实现依据迈从 M HUB 官方网页公开的 JavaScript，独立实现新协议族的设备识别、电量、当前 DPI 与回报率读取。**已有 `3837:1018` 接收器的用户失败日志，尚无成功读取电量、DPI 与回报率的真机验证，不能把目录覆盖、单元测试或 Windows 编译通过视为真机兼容认证。**

只启用下表的精确 VID/PID，以及同时满足 HID 描述符要求的接口。旧协议鼠标、蓝牙、未知 PID、固件升级模式不探测。本版本不发送设置、恢复默认、切换板载配置、配对或固件指令；DPI 与回报率始终只读。

Windows 仅选择 usage page `FF01` 或 `FF0B`、输入和输出均含 report ID `4D`、输入和输出报告长度均为 **64 字节（含 RID）**的 collection。官网 filters 未限定 usage 数值，本项目也不猜测。按物理 USB 父节点或 Container ID 归并，同型号的两只设备不会按 PID 合并。即便 PID 命中，没有这个控制接口也只识别，不尝试其他私有协议。

## 新协议报文

以下偏移均相对于包含 report ID 的 Windows HID 缓冲区；WebHID 的 `sendReport` 单独传 RID，数据为后面的 63 字节。

| 偏移 | 长度 | 公开编码器内容 |
| --- | ---: | --- |
| 0 | 1 | report ID `4D` |
| 1 | 1 | 固定 `01` |
| 2 | 1 | `flags`，默认 `01` |
| 3 | 1 | 参数长度 N |
| 4 | 2 | command，小端 |
| 6 | 1 | `bizCode`，默认 0 |
| 7 | 1 | `sequence`，默认 0 |
| 8 | N | 参数 |
| 8+N | 1 | flags=1 时，对偏移 2 到 7+N 异或 |
| 后续 | 余量 | 补 0，读取请求总长 64 |

例如 `0900` 无参数读取的前 9 字节为 `4D 01 01 00 00 09 00 00 08`，后续全 0。`0003` 参数为 `[profileIndex, direction]`，direction 0 为 X，1 为 Y。

**请求格式有直接来源；完整回复头语义仍有限制。** 官网接收代码只匹配命令，之后从 WebHID 数据偏移 7 取业务载荷，没有检查长度、校验、状态或序号。当前实验版保守地只接受与公开编码器对应的 RID=4D、64 字节、字节 1/2 为 1、bizCode/sequence 为 0、长度合法且 XOR 正确的回复；这是本项目的接受条件，尚未由实物证明所有固件都遵循。其他变体会显示格式错误，不能按超时或错误推断“不支持该鼠标”。

官网将业务载荷首字节 `FF` 视为尚未就绪并有限重读。本实现保留错误，不自动重发。每个查询只有一次发送、固定 3 秒期限，异步 `0600` 通知或其他命令不会延长期限。发送前清除当前句柄已有输入队列，不能保证其他进程同时使用官网/G HUB 类工具时绝对无旧应答竞争。建议读数核验时关闭其他驱动界面。

## 已实现的只读字段

业务载荷记为 P，不含 RID 与协议头。

### 0900：设备信息和电量

不带参数，P 至少 14 字节：

- `P[0:2]` VID，`P[2:4]` PID，均为小端。
- `P[4]` 官方字段 `maxConfigNum`，直接保留为原始元数据，不用于拒绝设备身份或电量读取。官方没有 1–3 的数量限制；值 4 也不意味着已确认配置索引 3 可供查询。
- `P[10]` 连接状态原值，未猜测其枚举含义。
- `P[11]` 充电状态：官网显示路径使用 1 表示充电；本实现接受 0/1，其余保留未知原因。
- `P[12]` 电量百分比，只接受 0–100。0 保留为 0，不擅自当断线；超出范围不会夹成 100%。

取得有效响应只表示协议通道返回了数据，不能据此证明无线鼠标状态或接收器缓存的新鲜度；当前缺少 `connectStatus` 枚举的可靠依据，保留此限制。每次读取先核对 VID/PID。直接 USB 返回型号须与 USB PID 一致，接收器返回型号须属于该接收器家族。

### 0002：当前配置和回报率

不带参数，P 至少 9 字节：`P[0]` 当前配置索引；`P[1]` 低 4 位为当前 USB DPI 档位，高 4 位为 USB 回报率编码；`P[2]` 含另一连接的回报率编码。官网当前 DPI 与回报率展示使用 USB 字段，本项目跟随该路径，不擅自根据“无线”标签切换到另一字段。

当前配置索引只接受官方流程明确使用的 `0、1、2`。官网 `JD` 遇到其他编号会退回 0，本实现保留具体编号并报错，避免展示另一配置的数据；该错误不会阻断独立的电量读取。

官方回报率表为 `[125,500,1000,2000,4000,8000]`，写编码对非零数组索引加 1，因此已确认生成的编码为 `0,2,3,4,5,6`。本实现只接受这些编码；不把未确认的 1 或越界编码夹到最近档位。V7、G3 V3 及 1016 关联仅接受 125/500/1000。

### 0003：DPI 表

请求参数 `[当前配置,0]` 读 X；P 为：配置、方向、档位数、当前档位索引、双轴标志，随后 6 个小端 uint16 DPI。双轴标志为 1 时再以 `[当前配置,1]` 读 Y。字段最少 17 字节。

本实现核对配置、方向、档位数 1–6、索引范围、双轴标志、DPI 非零且不超过官方型号上限。前后再读当前配置/档位与设备身份，若发生变化不返回拼接的 X/Y。单轴时 Y=X。界面范围的步长 1 表示只读 uint16 数值范围，不是承诺硬件支持任意整数步进写入。

## 写入研究与禁用原因

静态代码能确认：`0104` 参数为配置、DPI 档位、方向、DPI 小端；`0103` 写整张 DPI 表，读/写头字段顺序并不相同；`0102` 写当前性能块，包含回报率、DPI 档位、休眠、传感器和按键消抖等多个设置。

这些事实不足以把修改功能安全接入现有统一设置接口：官网 ACK 只按 command 匹配，状态含义、失败返回、保存时机没有完整证据，且 `0102` 会一并写其他设置。本版不开放写入，也不以“写后读到同值”代替尚未确认的身份和 ACK 语义。后续真机抓取应首先保持只读，补充回复头、PID 身份与状态证据后再决定扩大范围。

## 其他家族：明确不混用

官方同时包含旧取反 Feature Report 家族（0x11/0x12；`Hr/xG/Wo`）和 G3/G7 的其他协议分流。旧族可以看到 0x11/0x06 的电量/身份、0x12/0x67 的配置/DPI 表，以及取反编码，但其传输、报告长度、型号身份和写入确认都与 0x4D 族不同。G7 MAX 分流还使用 report ID 3 与 63 字节另一种校验。它们没有在本版本启用，不能将本表的 G3 V3 覆盖扩展到所有 G3，或把 A5 V3 Pro 覆盖扩展到 A5 V3。

## 验证边界

离线测试覆盖：精确请求向量；未知命令禁发；精确 VID/PID/usage/RID/长度筛选；正常电量、双轴 DPI、回报率；错误帧头、长度、XOR、命令；超时原始原因与单次发送；多设备隔离；接收器身份变化、读取中配置变化；未知数值；设置不发报文；关闭幂等；GUI 厂商、只读原因和句柄关闭；`maxConfigNum=4` 时的完整 GUI 读取、原始数量边界与未知当前配置不发 DPI 查询。

Windows amd64 原生编译、vet 及 4 项命名管道测试通过，覆盖超时取消后继续通信、短包进入协议校验、无关事件不延长截止时间，以及清空输入失败时不发送。命名管道、单元测试与 race 均使用合成报文，不是真机捕获。用户提供的 1.5.1 日志显示 `3837:1018` 接收器返回 `maxConfigNum=4`，触发了本项目错误的数量校验。1.5.2 移除该校验，继续验证身份、帧格式及当前配置索引。日志未包含原始报文或具体鼠标型号；本项目尚无修复后的迈从成功读数，硬件验证待补。
